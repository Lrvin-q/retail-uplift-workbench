# 小样本演示说明

本演示把“发邮件能否带来额外购买”变成一条可以运行、逐项检查的流程。所有人都是虚构客户，随机机制由代码设定，不包含任何真实客户信息。

1. 生成 2,000 名客户的实验前特征，随机分配邮件/无邮件，生成购买结果。
2. 为每次购买生成两条商品明细，明细中的交易总额重复；SQL 先归并交易，再聚合客户，左连接保留未购买者。
3. 独立核对 SQL 与 Python 购买标签，按全部分配客户计算 ITT 与 Newcombe 区间。
4. 按实验组分层划分训练/验证/测试，训练集拟合预处理和逻辑回归 T-Learner，另训普通购买预测基线。
5. 固定触达20%，只在测试集评估 SNIPS 策略值，用共同 bootstrap 构造策略差值区间；不根据测试结果调参。
6. 小型 LangGraph 适配器调用真实规则解析器，演示正常分析、待澄清、窗口限制、比较限制和干预后筛选阻断。

运行：`python -m dsa.portfolio_demo --out artifacts/demo`。产物：

|文件|内容|
|---|---|
|report.md / report.html|程序生成的演示报告|
|result.json|数值、参数、划分和配对差值|
|workflow_cases.json|五个问题的计划、原因与终态|
|customer_outcomes.sql|实际执行的 SQLite 聚合查询|

[已保存的样例](sample-output/report.md)来自默认参数的一次实际运行；其中正负结果都只解释为合成机制下的演示。

适配器只绑定“男装主题邮件对无邮件的14天购买率”这一合成比较；主题名用于复用现有规则，输出计划重新绑定到 `synthetic_demo` 与 `synthetic_email_demo_v1`，且标明 `data_kind=synthetic`，避免误认为真实实验。女装、访问率、多指标与名单服务不会被偷换成这个比较。

澄清只演示终态与缺失字段，不提供持久会话恢复。完整产品的 PostgreSQL 归档、恢复、模型登记、名单与 Streamlit 工作台保留在源码中，需要额外数据和服务，不属于这个无服务演示。

结构化结果中不可定义的统计量写为JSON `null`，例如无人触达策略的选中人群观察率；不填造零，也不输出非标准JSON的NaN。
