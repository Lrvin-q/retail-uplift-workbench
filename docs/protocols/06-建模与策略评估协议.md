## 1. 二元比较的目标总体、干预与结果

| 项目 | 定义 |
|---|---|
| 数据集 | `hillstrom@2008-03-20` |
| 目标总体 | 过去 12 个月内有购买记录的零售客户（= 全部 64,000 行） |
| **干预** | `Mens E-Mail`（收到男装主题邮件） |
| **对照** | `No E-Mail`（未收到邮件） |
| **结果** | `conversion`（实验后两周内是否购买） |
| **结果窗口** | 实验后 14 天（固定） |
| 估计目标 | 条件平均干预效果 **CATE**：$\tau(x) = E[Y(1) - Y(0) \mid X = x]$ |

### 1.1 实验前特征（允许作为模型输入）

`recency, history_segment, history, history_band, mens, womens, zip_code, newbie, channel`

### 1.2 禁止作为输入（干预后结果）

`visit, conversion, spend`

> ⚠️ 违反即构成**数据泄漏**。`dsa.stats.aggregates.assert_no_post_treatment_in_features`
> 提供程序化防线；建模代码必须在拟合前调用它。

### 1.3 明确不做的估计

- **不估计个体真实增量。** 每名客户只观测到一个干预结果，`Y(1)` 与 `Y(0)` 不可能同时被观测到，
  因此**个体增量标签在原理上不可得**。任何"个体效果预测准确率"都无意义。
- **不给任意客户级预测分数附"可靠 95% 置信区间"。** 灵活机器学习模型不自动提供有效的条件效果区间
  （参见 [EconML 的 Meta-Learners 说明](https://www.pywhy.org/EconML/spec/estimation/metalearners.html)）。
  第一版只对**总体实验效果**与**按固定规则评估的群体策略**报告不确定性。

## 2. 从三组实验形成二组比较的规则与条件化分配概率

### 2.1 选择规则

从三组中取出 `Mens E-Mail` 与 `No E-Mail` 两组，**丢弃** `Womens E-Mail` 组。

> 这不是随机抽样，而是**按组别取值确定性地筛选**。因此分析人群是
> 「被分配到 Mens 或 No E-Mail 的 42,613 名客户」，**不是**全部 64,000 名客户。

### 2.2 条件化分配概率（**策略评估的关键输入**）

原实验三组等概率分配：$P(\text{arm} = a) = 1/3$ 对每个 $a \in \{mens, womens, control\}$。

在**限定于 `{mens, control}`** 的条件下：

$$e(x) = P(\text{arm} = mens \mid \text{arm} \in \{mens, control\}) = \frac{1/3}{1/3 + 1/3} = \frac{1}{2}$$

同理 $P(\text{arm} = control \mid \cdot) = 1/2$。

**结论：条件化倾向得分是常数 0.5，且与实验前特征 $x$ 无关。**

这一点很重要，它给出两个直接后果：

1. **随机化在条件化后仍然成立**——处理分配与 $x$ 独立，因此简单的差值估计无偏。
2. **逆概率加权（IPS）权重退化为常数** $1/e = 2$。这使离线策略评估的
   IPS 估计量大幅简化，但**不改变其有效性前提**（见 §5）。

> 记录这条推导，是因为它把「实验是三组」与「建模是二组」之间的口径差异说清楚了。
> 若直接假设"二组实验、各 50%"，结论相同，但推理过程被跳过了——
> 一旦将来改用其他组别组合或不等比例分配，跳过推导就会出错。

### 2.3 数据版本与人群规模

| 项目 | 值 |
|---|---|
| Mens E-Mail | 21,307 |
| No E-Mail | 21,306 |
| **合计（建模人群）** | **42,613** |

## 3. 数据划分

### 3.1 三分法（互不重叠）

| 集合 | 比例 | 用途 |
|---|---|---|
| 训练集 train | 60% | 拟合预处理与模型 |
| 验证集 valid | 20% | 选择模型与策略参数 |
| **最终留出集 test** | 20% | **只用于最终评估，不参与任何选择** |

### 3.2 划分约束

1. **按组别分层**（stratified by arm）：每个集合中 `mens` 与 `control` 的比例保持约 1:1。
2. **客户级划分**：一名客户整体进入某一个集合，绝不跨集合。
3. **固定随机种子**：默认 `20261011`，写入模型登记。
4. **划分结果必须可复现**：相同种子与相同数据必须产生完全相同的划分。

### 3.3 只用训练集拟合预处理

编码（类别 → 数值）、缺失处理、标准化等**只在训练集 `fit`**，再 `transform` 到验证集与测试集。

> 违反此规则会通过预处理把测试集信息泄漏进训练过程。

## 4. 模型

### 4.1 购买预测基线

预测 $P(Y = 1 \mid X = x)$，在 `mens` 组与 `control` 组上分别训练或合并训练（二者都做，取验证集更优者）。

用途：作为**策略基线之一**（按预测购买概率排序），以及**对照**——
但**绝不用它的 AUC 证明增量模型有效**。

### 4.2 简单 T-Learner（增量模型）

分别拟合两个结果模型：

$$\hat{\mu}_1(x) \approx E[Y \mid X = x, W = 1], \qquad \hat{\mu}_0(x) \approx E[Y \mid X = x, W = 0]$$

增量估计：

$$\hat{\tau}(x) = \hat{\mu}_1(x) - \hat{\mu}_0(x)$$

### 4.3 基础学习器

**第一轮固定一种，不做模型竞赛。** 采用 `LogisticRegression`：

- 理由：结果 `conversion` 是二值变量；购买率极低（~1%），线性模型在无强非线性证据时是稳妥起点；
  可解释、训练快、与统计基线的口径差异小。
- 预处理：类别特征用 `OneHotEncoder(handle_unknown="ignore")`；数值特征用 `StandardScaler`。
  **全部在训练集拟合。**
- 第一版**不做**超参数搜索、不做神经网络、不做多模型对比。

## 5. 离线策略评估

### 5.1 策略定义

策略 $\pi$ 在给定触达比例 $q$ 下，按某个打分 $s(x)$ 从高到低选取前 $q$ 比例的客户施以干预。

#### 5.1.1 三类概率必须分开（v1.2 修正）

历史缺陷（审查 5.2）：**同名策略在两处代表不同的模型输出**——离线评估里的 `propensity`
用的是 $\hat\mu_0(x)$，而名单接口里的 `propensity` 按 `propensity_score`
（跨组合并训练的购买预测）排序。两条排序不同，名字却一样。

三类量从此**分别命名、分别取值**：

| 概念 | 含义 | 数据来源 | 是否随 $x$ 变化 |
|---|---|---|---|
| **分配倾向概率** | $P(\text{被分到干预组} \mid x)$，真值 $\equiv 0.5$ | **不来自模型**（§2.2 由实验设计推导） | 否 |
| **无干预购买概率** | $P(\text{购买} \mid \text{对照}, x)$ | T-Learner 的 $\hat\mu_0$ → `customer_scores.mu0` | 是 |
| **合并购买预测分数** | $P(\text{购买} \mid x)$，跨组合并训练 | 合并结果模型 → `customer_scores.propensity_score` | 是 |

#### 5.1.2 策略表（唯一权威定义）

| 策略 | 打分 $s(x)$ | `customer_scores` 列 |
|---|---|---|
| `random` | 固定种子的均匀随机数 | —（名单接口用 `customer_id` 给出稳定顺序） |
| `purchase_probability` | 合并购买预测 $\hat P(Y=1\mid x)$ | `propensity_score` |
| `control_probability` | 无干预购买概率 $\hat\mu_0(x)$ | `mu0` |
| `uplift` | 预测增量 $\hat\tau(x)=\hat\mu_1-\hat\mu_0$ | `uplift` |
| `all_treat` | 全部触达（补充参照，资源不同） | — |
| `none` | 全部不触达（补充参照，资源不同） | — |

**旧名 `propensity` 一律拒绝**（返回错误码 `E_TOOL_001` 并提示改用
`purchase_probability` 或 `control_probability`）：静默接受旧名正是本条缺陷的成因。

**唯一真源**：`dsa.models.policy.POLICY_DEFINITIONS`。离线评估取打分用
`scores_from_frame`（列名来自 `policy_score_columns()`），名单接口排序用
`POLICY_ORDER_COLUMNS`——两者派生自同一个常量，不允许各自硬编码列名。
`tests/test_stage4_policy_contrasts.py` 有一条测试断言"离线评估取的那一列"
与"名单接口排序的那一列"是**同一个标识符**。

### 5.2 评估方法

#### 5.2.1 ⚠️ v1.0 的示意式是错的（已修正）

v1.0 曾给出这样一个"示意式子"：

> $\hat{V}(\pi) = \frac{1}{n}\sum_i \frac{\mathbb{1}[W_i = \pi(X_i)] \cdot Y_i}{e(X_i)} \cdot \frac{1}{?}$

**这是错的**，错在它算的是**策略下的结果水平**，不是**相对不触达的增量**。
两种写法的差异不是记号问题，而是实质性的：

- 当 $\pi \equiv 1$（全部触达）时，该式直接输出**干预组的购买率**（约 1.25%）；
  而真实增量是约 **0.68 个百分点**——差的那部分正是**基线购买率**。
- 模拟量化（同质场景，n=20000，200 次重复）：

  | 场景 | 真值 | v1.0 示意式均值 | 偏差 |
  |---|---|---|---|
  | q = 0.30 | +0.002040 | +0.003253 | **+0.001213（真值的 59%）** |
  | 全部触达 | +0.006800 | +0.015824 | **+0.009024（≈整条基线购买率）** |

因此该式**不得用于任何报告**。实现中保留它仅作反例：
`dsa.models.policy.illustrative_sketch_estimate`，并有测试量化其偏差。

> **教训**：协议里的公式即便标注为"示意"，也会被下游当作依据实现。
> 凡涉及估计量的式子，必须写明**它估的是什么**，并在模拟中核对无偏性后才写进协议。

#### 5.2.2 正确形式（v1.1 起采用）

记 $\pi_i = \mathbb{1}[\text{策略给客户 } i \text{ 发邮件}]$，
$S_1 = \{i : \pi_i = 1, W_i = 1\}$，$S_0 = \{i : \pi_i = 1, W_i = 0\}$：

$$\hat{V}(\pi) \;=\; \hat{P}(\pi = 1)\;\Bigg[\;
\underbrace{\frac{\sum_{i \in S_1} Y_i / e_i}{\sum_{i \in S_1} 1 / e_i}}_{\text{Hájek 估计：} E[Y(1) \mid \pi = 1]}
\;-\;
\underbrace{\frac{\sum_{i \in S_0} Y_i / (1 - e_i)}{\sum_{i \in S_0} 1 / (1 - e_i)}}_{\text{Hájek 估计：} E[Y(0) \mid \pi = 1]}
\;\Bigg], \qquad \hat{P}(\pi = 1) = \frac{1}{n}\sum_i \pi_i$$

**语义**：增量 = **干预侧水平 − 同一份名单在对照侧的反事实水平**，
再乘以触达比例折算为总体人均增量。

$\hat{P}(\pi=1)$ 这一因子不可省略——它把"只对这一小部分人施治"折算成总体口径。

> ⚠️ **不能用「减去 $\hat{V}(\text{none})$」来把水平变成增量。**
> $\hat{V}(\text{none})$ 是**空策略**的值，不是"这份名单的基线水平"。
> 要减的是**限制在同一份选中名单上**的对照臂反事实水平 $E[\pi(X)Y(0)]$，
> 它随策略 $\pi$ 变化。这是 v1.0 示意式真正缺的东西。

#### 5.2.3 常数倾向下的化简

本项目 $e(x) \equiv 0.5$（§2.2）。此时 $1/e$ 与 $1/(1-e)$ 在两个 Hájek 分量的
分子分母里**同时出现、整体约掉**，于是上式**精确退化**为：

$$\hat{V}(\pi) \;=\; \hat{P}(\pi = 1) \times \Big( \overline{Y}_{S_1} - \overline{Y}_{S_0} \Big)$$

即「**选中医访臂与对照臂的普通购买率之差 × 触达比例**」。

两个推论：

1. **估计值对 $e$ 的取值不敏感**（$e$ 为常数时约掉），有测试覆盖。
2. 这个化简**只在 $e$ 为常数时成立**。若将来改用以特征为条件的倾向得分，
   必须回到 §5.2.2 的加权形式。

#### 5.2.4 实现与核对要求

- 公式的**正确性必须先用已知机制的模拟验证**（§7），确认无偏后才可用于留出集评估。
- `dsa.models.policy.snips_estimate` 对**空选择**返回 `nan`（估计量不撒谎）；
  `none` 策略在**报告行组装处**按定义填 `0`（见 §5.2.5）。
- 区间由留出集 **bootstrap** 给出（固定种子）。

#### 5.2.5 「全部不触达」是定义值，不是估计值

`none` 策略的增量**按定义恒为 0**：$\mathbb{E}[0 \cdot \tau(X)] = 0$。
它必须显示为 `0`（区间为退化的 `[0, 0]`），而不是 `nan`——
`nan` 在报告里会渲染成「无定义」，让业务读者误以为数据出了问题。

实现上通过 `PolicyScore.is_definitional` 标记该行，报告层据此把它渲染为参照点、
不参与区间宽度比较。

### 5.3 有效性前提（必须逐条核查并记录）

| 前提 | 本项目状态 |
|---|---|
| 无混淆（unconfoundedness） | ✅ 随机分配保证 |
| 重叠（overlap）/ 正值性 | ✅ $e(x) = 0.5$，远离 0 与 1 |
| SUTVA（无干扰、无多版本干预） | ⚠️ **假设**，不可验证。若客户之间会互相影响则不成立 |
| 分配概率已知且正确 | ✅ 由实验设计推导（§2.2），非估计 |

### 5.4 ⚠️ 评估结果的表述边界

留出集上的策略评估是**回顾性评估**，不是对未来的预测：

- 名单是**演示输出**，不能被描述成"这些历史客户未来实际会发生的购买变化"。
- **没有成本数据**，因此不得声称净收益、ROI 或预算决策。
- 全部触达与全部不触达**资源消耗不同**，只能作为补充参照，不能与固定比例策略直接排名。

### 5.5 模拟验证的区间覆盖率（v1.1 起）

边际区间的覆盖率由 `dsa.models.policy_simulation` 用已知真值的模拟核对（§7）。

### 5.6 策略差异：只能看差值区间（v1.2 新增，F09）

#### 5.6.1 ❌ 「两条边际区间是否重叠」不是差异检验

两个策略跑在**同一份留出客户**上，两个估计是**相关**的。用边际区间是否重叠来判断差异，
在统计上不成立。可手算的反例（`tests/test_stage4_policy_contrasts.py`）：

> 两个估计的标准误都是 1、相关系数 0.95 → **差值**标准误
> $\sqrt{1+1-2\times0.95}=\sqrt{0.1}=0.3162$。
> 边际 95% 区间为 $[-1.96, 1.96]$ 与 $[-0.96, 2.96]$（明显重叠），
> 而估计差值为 1 时，差值区间 $[0.3802, 1.6198]$ **排除 0**。
> 2000 次蒙特卡洛：边际区间重叠率 1.0000，配对判据的检验力 0.8905。

在**项目自己的估计量**上同样复现（合成留出集，n=20000，q=0.30，两个名单高度重叠、
重抽样相关系数 0.9448）：两条边际区间重叠，而配对差值区间
$[-0.001981, -0.000152]$ 排除 0。

#### 5.6.2 正确做法：同一次共同 bootstrap 内的配对差值

对每个触达比例 $q$ 与每一对策略 $(a,b)$，在第 $b$ 次重抽样里两个策略**共用同一批索引**，
差值就是

$$\hat\Delta_b = \hat V_a^{(b)} - \hat V_b^{(b)}$$

差值区间取 $\{\hat\Delta_b\}$ 的 $2.5\%/97.5\%$ 分位（只计两个策略都算出有限值的那些次）。
**独立重抽样会丢掉相关性、把区间做宽**，那样的差值区间是错的——
`tests/test_stage4_policy_contrasts.py` 里有一条测试把生产实现与"测试侧独立写一遍的
配对 bootstrap"逐位比较，另有一条对照测试量化"配对 vs 独立"的区间宽度差。

**模拟表现**（协议 §7 要求）：已知真值下配对差值区间的覆盖率由
`policy_simulation.run_difference_coverage` 与 `diagnose_overlap_vs_paired` 给出。

#### 5.6.3 结论口径

- 差值区间**排除 0** → 在这一份留出集上两个策略的总体增量**有可检出的差别**；
  这是单次回顾性评估的结果，不是对未来的承诺。
- 差值区间**包含 0** → **当前留出集无法区分**这两个策略。
  ⚠️ 这**不表示**两个策略相同（不是等价性检验），也**不表示**哪一个更优。
- 报告**不得**再出现"边际区间重叠 ⇒ 未检出显著差异"这类表述。

## 6. 预先固定的评估规则

**以下规则必须在看到留出集结果之前确定，写死在配置里。**

1. 触达比例集合：$q \in \{0.05, 0.10, 0.20, 0.30, 0.50\}$。**全部报告，不只报最好的那个。**
2. 主指标：IPS/SNIPS 估计的总体增量（绝对百分点）。
3. 辅助指标：选取人群的实际观测购买率（仅描述，有偏，不作为策略优劣依据）。
4. **不看留出集调参**：模型与策略参数在验证集上确定后即冻结。
5. **不反复挑选随机种子**：种子固定为 `20261011`，一旦确定不再更换。
6. 不确定性用 **bootstrap**（固定种子）在留出集上重抽样给出，报告区间而非只报点估计。
7. **（v1.2 新增）主要比较预先固定**：`CONTRAST_PRIMARY_FRACTION = 0.10`、
   `CONTRAST_PRIMARY_POLICY = "uplift"`、`CONTRAST_PRIMARY_REFERENCE = "random"`，
   即「触达 10% 时，按预测增量排序 相对 随机选择」。
   选择 10% 的理由（**与留出集结果无关**，全部在看结果之前就能说清）：
   - 十分位是项目里**已经存在**的默认触达深度——`sql/004_policy_queries.sql` 的
     `top_decile_check` 把 `:fraction` 默认成 `0.1`，沿用它可以避免"报告一套、核对另一套"；
   - 它是固定比例集合里最小两档之一（0.05 只有约 426 人，名单与区间都太薄），
     同时是真实营销里最常见的投放深度；
   - 与 0.30 相比更接近"真要做一次触达"的规模，避免用最大的比例（区间最窄）
     去制造显著性——后者正是 AGENTS.md §3.4 禁止的做法。
8. **（v1.2 新增）其余比较一律标注"探索性"**，并且必须写明
   「**未做多重比较校正（未控制族错误率）**，结论只能作为下一步的假设」。
   每个比例下有 6 对排序策略（`CONTRAST_PAIRS`），全表 30 条差值，其中只有 1 条是主要比较。

## 7. 模拟验证（必须完成）

在固定留出集上评估**之前**，用已知机制的模拟数据验证策略评估程序：

1. **已知真实 CATE 的模拟**：设定 $\tau(x)$ 依赖 $x$（例如只对某段 `history` 的客户有效果）。
2. 检验：按真实 $\tau(x)$ 排序的策略，其 IPS 估计是否接近真实总体增量；
   按预测购买概率排序的策略是否确实不如按真实增量排序。
3. **覆盖检查**：重复模拟下，策略增量估计的区间覆盖率是否接近名义水平。
4. 明确记录**模拟假设与实际数据的差异**。

## 8. 版本登记与产物

每次训练必须登记：

| 项目 | 要求 |
|---|---|
| 数据版本 | `hillstrom@2008-03-20` 及其 SHA256 |
| 特征集合 | 明确的列名列表（含预处理后的特征名） |
| 划分 | 种子、比例、各集合人数、各组别人数 |
| 模型 | 类型、全部超参数、基础学习器 |
| 代码版本 | git commit |
| 客户分数 | **保存到数据库**，与模型版本、数据版本关联 |
| 评估配置 | 触达比例集合、评估方法、bootstrap 种子 |

产物：

- 模型登记行 + 客户分数表
- 策略比较报告（固定模板）
- 模拟验证记录

### 8.1 训练是明确的离线任务

训练**不是**在线服务的一部分，也不由 Agent 触发。Agent 只能**读取已登记的模型与分数**。

### 8.2 模型身份指纹（v1.2 新增，F10）

**问题**：只按 `model_key` 做幂等，会允许同一个 key 接受**不同**的训练配置——
接口返回成功与原 `model_id`，数据库里留的却是旧参数/旧种子/旧代码版本；
再加上分数写入是"冲突不更新"，重新训练就可能把新策略评估挂到旧版本下，
版本对应关系被破坏。

**规则**：`model_key` + **身份指纹** 一起构成模型身份。指纹覆盖

| 字段 | 说明 |
|---|---|
| `model_type` | `t_learner` / `outcome_model` |
| 数据集版本 | `datasets.version_label` |
| 实验 / 比较 | `experiments.experiment_key` / `comparison_key` |
| `feature_columns` | **有序**——顺序是模型语义的一部分 |
| `base_learner` | 基础学习器 |
| `params` | 全部超参数（规范化 JSON） |
| `split_config` | seed / ratios / counts / arm_counts |
| `code_version` | git commit（含工作区脏标记） |
| 预处理配置 | `dsa.models.features.preprocessing_config()` |

指纹 = `sha256:` + 规范化 JSON 的 sha256（`dsa.models.registry.compute_identity_fingerprint`）。
规范化保证**键序、`1` 与 `1.0`、numpy 标量不影响指纹**（有测试）。

语义：

- 指纹**完全相同** → 幂等，返回已有 `model_id`，不新增行、不改任何已存字段；
- 指纹**不同**（同一 `model_key`）→ 抛 `IdentityMismatchError`，
  消息里**逐字段**列出旧值 → 新值，并提示**换一个新的 `model_key`**。
  **不会**静默返回旧 id，也**不会**覆盖旧配置；`scripts/train_and_evaluate.py`
  在这种情况下**报错中止**（退出码 2），不自动改 key。

**分数写入的"冲突不更新"为什么安全**：分数行由 `unique (model_id, customer_id)` 约束，
而 `model_id` 只能由 `register_model` 返回；指纹不同的配置根本拿不到旧 `model_id`，
因此不存在"用新配置的分数去撞旧版本的行"这条路径。
`tests/test_stage4_identity.py` 有一条测试锁住这条不变式。

**既有库迁移**：`sql/006_policy_contrasts_and_identity.sql` 加列（幂等 `add column if not exists`），
`dsa.models.registry.backfill_identity_fingerprints` 从**库内已存字段**重算并回填，
不写任何常量。回填之后，指纹可以只从数据库重算出来。

**评估绑定不可变版本**：策略评估只依赖"已登记版本的分数 + 留出集 + 固定评估规则"，
因此口径变更（例如本节的命名与差值区间）**不要**重跑训练，用
`python -m dsa.models.reevaluate <model_key>` 按已存分数重算并核对。
