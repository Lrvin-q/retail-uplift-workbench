## 1. 目的与适用范围

本协议适用于**已经结束的、固定观察窗口的随机对照实验**的复盘分析。

**适用**：数据来自明确随机分配的实验，有干预组与对照组，结果在固定窗口内观测。

**不适用**：缺少随机化信息的普通观察性业务数据。对这类数据，系统只提供描述性分析，
或提示需要另行制定识别方案，**不得沿用本协议输出因果结论**。

## 5. 主要比较与次要比较

### 5.1 主要比较（Primary）

> **Mens E-Mail（干预） vs No E-Mail（对照）**

这是第一版唯一用于**确认性结论**的比较。

### 5.2 次要比较（Secondary / 探索性）

> **Womens E-Mail（干预） vs No E-Mail（对照）**

**必须遵守的约束**：

- 次要比较的结果一律标记为**探索性**，不用于确认性结论。
- 若在同一份报告中同时给出主要与次要比较，必须说明**多重比较问题**，
  并给出经校正的判定（Bonferroni：α 调整为 0.05/2 = 0.025）。
- 报告中不得只挑显著的比较汇报。

### 5.3 ⚠️ 关于「为什么选 Mens 作为主要比较」的诚实记录

**本项目在选定主要比较时已经知道两个干预组的观测效果**（Mens 的购买率高于 Womens）。
这是一个**已知的选择性偏倚来源**，必须记录，不能隐去。

处理方式：

1. 选择理由以**项目叙事**为主（《项目详细思路.md》§5 场景 A 以「男装邮件」为例），
   而非「因为它效果更大」。
2. **Womens 的数据完整保留**，次要比较照常报告，不隐藏。
3. 结论中不允许出现「我们检验了多个组，Mens 显著所以它是有效的」这类表述。
4. 若后续要严谨地做两个干预组的对比，必须另行制定多重检验规则——本版不做。

> 这条记录本身就是项目的一部分：它示范了「口径决策如何被记录下来以便他人复核」。

## 6. 随机化单位与分析单位

| 项目 | 定义 |
|---|---|
| 随机化单位 | **客户**（一名客户被独立随机分配到一组） |
| 分析单位 | **客户**（与随机化单位一致） |

**⚠️ 单位一致性是本协议最重要的约束之一。** 随机化单位与分析单位必须一致，
否则会低估方差、产生虚假显著性。

具体禁令：

- **不得**把事件行当作独立样本（本数据集无事件级数据，但下游派生表可能有）。
- **不得**因为一名客户有多次行为就把它重复计入分母。
- 所有聚合必须以「客户」为唯一计数单位，用 `COUNT(DISTINCT customer_id)` 或等价的
  唯一约束保证。

## 8. 指标定义

### 8.1 主要指标：购买率（Conversion Rate）

$$\text{购买率}_g = \frac{\text{组 } g \text{ 中 } conversion = 1 \text{ 的客户数}}{\text{组 } g \text{ 中纳入分析的客户数}}$$

| 要素 | 定义 |
|---|---|
| 分子 | `conversion = 1` 的**客户数** |
| 分母 | **全部**被随机分配到该组的客户数 |
| 单位 | 客户 |

> **绝对禁令：分母不得按 `visit`（访问行为）过滤。**
> `visit` 是**干预后**的结果变量。若按访问者筛选分母，就是在干预后选择样本，
> 会破坏随机化、引入碰撞偏倚（collider bias），得到的不是干预效果。
> 这是本协议中最容易被违反、后果最严重的一条。

### 8.2 次要指标

| 指标 | 分子 | 分母 | 说明 |
|---|---|---|---|
| 访问率 | `visit = 1` 的客户数 | 该组全部客户数 | 同为干预后结果，口径同理 |
| 人均消费 | 该组 `spend` 总和 | 该组全部客户数 | **包含未购买客户（spend=0）**，否则会高估 |
| 购买者人均消费 | 该组 `spend` 总和 | 该组 `conversion=1` 的客户数 | ⚠️ **条件于干预后结果**，仅作描述，不得用于因果结论 |

### 8.3 效果量

| 效果量 | 定义 | 用途 |
|---|---|---|
| 绝对差异（风险差 RD） | $p_{treat} - p_{ctrl}$ | **主要效果量** |
| 相对变化（风险比 RR） | $p_{treat} / p_{ctrl}$ | 辅助展示 |
| 相对提升 | $(p_{treat} - p_{ctrl}) / p_{ctrl}$ | 辅助展示，等价于 $RR - 1$ |

**相对变化的边界处理**：当对照组购买率为 0 或极小时，相对变化不稳定或无定义。
此时**只报告绝对差异**，并显式说明相对变化不可靠，不得输出 `inf` 或极大的百分比。

## 9. 缺失值处理

**本数据集的实测结果：全部 12 个字段均为 0 缺失。**

因此第一版**不触发**任何缺失处理逻辑。但仍须定义规则以备派生表使用：

| 情况 | 处理 |
|---|---|
| 组别（`segment`）缺失 | **排除该客户**并计数报告。无法归组就无法分析 |
| 结果字段（`conversion` / `visit` / `spend`）缺失 | **不视为 0**，也不静默剔除。单独计数并报告覆盖率；覆盖率低于阈值时按异常处理（见报告结构文档异常码） |
| 特征字段缺失 | 建模阶段单独处理，在训练集上拟合插补规则 |

> **关键原则：缺失结果不得被当作「未购买」。** 这两者在业务上含义完全不同。

## 10. 样本排除规则

**第一版主要比较的排除规则：无。**

即：`segment ∈ {Mens E-Mail, No E-Mail}` 的**全部客户**都进入分析，
不做任何基于行为或特征的过滤。

**唯一允许的排除**：组别缺失（本数据集为 0 例）。

若将来引入排除规则，必须满足：

1. 排除发生在**看结果之前**，且基于**实验前**信息；
2. 排除规则写入本协议并版本化；
3. 报告中记录排除前后的人数变化。

## 11. SRM 检查（样本分配比例失衡）

### 11.1 预期比例来源

> **预期比例 = 1/3 : 1/3 : 1/3**
>
> 来源：原始实验说明明确写出「1/3 were randomly chosen to...」（见数据来源核查记录 §3.3）。

这是**权威来源**。协议明确禁止「从观测到的比例反推预期比例」——
那样做会让 SRM 检查永远通过，失去意义。

### 11.2 检查方法

| 项目 | 规定 |
|---|---|
| 方法 | 卡方拟合优度检验（3 组） |
| 原假设 | 观测计数符合 1/3 : 1/3 : 1/3 |
| 检验水平 | **α = 0.001**（SRM 用比常规更严格的阈值） |
| 输出 | 卡方统计量、自由度、p 值、各组观测/预期计数及偏差 |

第一版针对**三组整体**做 SRM 检查。若做主要比较的二组子集检查，需另行说明其预期
比例（由三组等分条件推导为 1:1），并注明这是推导而非原始说明直接给出。

### 11.3 结果解释规则（重要）

- **SRM 异常 ⇒ 提示需要诊断**，可以阻断因果结论并生成诊断报告。
  但**不得自动断定异常原因**（可能是分流 bug、日志丢失、数据导出问题等多种原因）。
- **SRM 通过 ⇒ 不能证明随机化完全正确。** 它只说明样本比例与预期一致，
  无法检验随机化是否在其他维度上失衡，也无法排除系统性偏差。
- 报告中必须原样体现以上两条边界。

## 12. 统计方法与不确定性

### 12.1 主要指标（购买率差异）

| 环节 | 方法 | 理由 |
|---|---|---|
| 组内比例区间 | **Wilson score interval** | 小比例 + 大样本下比 Wald 区间更可靠，不会越界 |
| 组间差异区间 | **Newcombe hybrid score interval** | 由两个 Wilson 区间组合，小比例下覆盖率优于 Wald |
| 假设检验 | **卡方检验**（无连续性校正）；当任一格期望频数 < 5 时改用 **Fisher 精确检验** | 标准做法，需核对适用条件 |
| 相对风险区间 | Katz 对数法（或 MOVER） | RR 的常规区间方法 |

> **不采用 Wald 区间作为主要方法**：购买率约为 0.6%~1.3%，属于小比例，
> Wald 区间在此场景下覆盖率不足且可能越界。这是「核对方法适用条件」的具体体现。

### 12.2 次要指标

| 指标 | 方法 |
|---|---|
| 访问率 | 同购买率（Wilson + Newcombe + 卡方/Fisher） |
| 人均消费 | Welch t 检验（不假设方差齐性）+ bootstrap 置信区间；或两组独立样本的置换检验 |
| 消费分布 | 高度零膨胀（中位数为 0），必须报告零值占比，不得只报均值 |

### 12.3 显著性水平

| 用途 | 水平 |
|---|---|
| 主要比较 | **α = 0.05，双侧** |
| 次要（探索性）比较 | 报告时注明多重比较问题；同时给出 Bonferroni 校正后的判定（α = 0.025） |
| SRM 检查 | **α = 0.001** |

### 12.4 可复现性要求

每次分析必须固定并记录：

- 数据版本与文件哈希
- 统计方法与其参数（检验类型、区间方法、α、是否校正）
- 程序版本（代码提交哈希）
- 随机种子（凡涉及随机的方法，如 bootstrap、置换检验、数据划分）

相同输入与配置必须产生相同结果。**未固定随机种子的随机方法不得进入报告结论。**

### 12.5 策略**差异**的推断（v1.1 新增）

**适用场景**：比较两个固定触达规则（如「按预测增量选前 10%」与「随机选前 10%」）
在同一留出集上的价值估计。

**方法**：在**同一次共同 bootstrap** 内计算配对差值。

```
对 b = 1..B：
  用同一组重抽样索引 i_b 同时得到 V_A^(b) 与 V_B^(b)     ← 关键：索引共享
  记录 Δ^(b) = V_A^(b) − V_B^(b)
报告 Δ 的百分位区间
```

**为什么必须配对**：两个策略作用在**同一批留出客户**上，其估计值**相关**。
若各自独立重抽样，差值区间会按"独立"来算，而真实的标准误更小（也可能更大），
区间因此失去名义覆盖率。共享索引使相关性被保留在 Δ 里。

**❌ 已废止的做法**：用「两个策略**各自的**区间是否重叠」判断差异。

反例（写在这里以免被重新发明）：若两个估计的标准误都是 1、相关系数 0.95，则

```
SE(Δ) = sqrt(1 + 1 − 2×0.95) = 0.316
```

**各自的 95% 区间可以明显重叠，而 Δ = 1 时其差值区间仍排除 0。**
反过来也成立：各自区间不重叠时差值未必显著。
**区间重叠与否不是差异检验，两者之间没有单调关系。**

**预先固定**（避免事后挑选）：

- 主要触达比例与主要对照**在评估前固定**（见 `docs/06-建模与策略评估协议.md`）；
- 其他比较一律标注为**探索性**；未做多重比较校正时必须写明。

**结论强度**：只能依据**差值区间**下结论。区间包含 0 时，
正确表述是「**当前留出集无法区分这些策略**」，而不是"它们一样好"，
更不是"某个策略更好"。

> 本项目 8,523 人的留出集上，各策略差值区间均包含 0 ——
> 因此本项目**不裁定**哪种客户选择策略更优。这是结论，不是缺陷。

### 12.6 措辞禁令（补充）

| ❌ 不允许 | ✅ 应当 |
|---|---|
| 「两个策略的区间重叠，说明没有显著差异」 | 「配对差值区间包含 0，**当前留出集无法区分**这两个策略」 |
| 「区间不重叠，所以有显著差异」 | 「以配对差值区间为准；差值区间排除 0 才可称有差异」 |

## 13. 效果解释规则

### 13.1 必须分开表达的四件事

**统计显著性 ≠ 效果大小 ≠ 业务价值 ≠ 数据可信度。** 报告必须分别陈述：

1. **统计证据**：差异是否超出随机波动（p 值、置信区间）
2. **效果大小**：绝对差异是多少，相对变化是多少
3. **业务阈值**：这个幅度是否值得投放（需要成本数据；本项目没有成本数据，
   因此**只能陈述效果，不能声称净收益**）
4. **数据可信度**：SRM 是否通过、覆盖率是否正常、有无其他异常

### 13.2 措辞禁令

| ❌ 不允许 | ✅ 应当 |
|---|---|
| 「不显著，说明没有效果」 | 「未检出统计显著差异；在现有样本量下无法排除小效应存在」 |
| 「显著，所以应当投放」 | 「差异在 α=0.05 下显著；是否投放还需结合成本、触达限制与业务阈值」 |
| 「邮件使购买率提升 X%」而未说明窗口 | 「在实验后两周窗口内，购买率绝对提升 X 个百分点」 |
| 用相对变化掩盖极小的绝对差异 | 绝对差异与相对变化同时给出 |
| 只报显著的指标 | 主要指标与预先指定的次要指标全部报告 |

### 13.3 不确定性表达

- 只对**总体实验效果**和**按固定规则评估的群体策略**报告不确定性。
- **不给任意客户级预测分数附「可靠 95% 置信区间」。** 灵活的机器学习模型
  不自动提供有效的条件效果区间。

## 14. 第一版明确不支持的请求

| 请求类型 | 处理 | 理由 |
|---|---|---|
| 任意日期窗口（「只看最近一个月」） | **阻断** | 数据无日期字段，窗口固定为两周 |
| 中途查看后的上线/停止决策 | **阻断** | 无多重检验与序贯分析规则 |
| 按干预后行为筛选人群（「只看访问者」） | **阻断** | 破坏随机化，见 §8.1 |
| 「换个口径再算一次」（为找显著结果） | **阻断** | 统计不显著不得成为修改分析条件的理由 |
| 自动执行邮件投放 | **不受支持** | 系统不连接投放通道 |
| 实时分流 / 线上实验平台 | **不受支持** | 超出第一版范围 |
| 净收益 / ROI / 预算优化 | **不受支持**（无成本数据） | 可展示明确标注的情景计算 |
| 个体真实增量标签 | **不受支持** | 每名客户只观测到一个干预结果，数据原理上不提供 |
| 用购买预测 AUC 证明增量模型有效 | **阻断** | 两者评价的是不同问题 |
| 跨数据集拼接客户或互为对照 | **阻断** | 不同数据适配必须隔离 |

## 15. 报告必填信息

每份分析报告必须包含并可追溯：

1. 用户问题与**确认后的**分析计划
2. 数据来源、**数据版本**、分析对象、指标定义
3. 数据质量检查与阻断项

## 16. 建模阶段的口径（预留，阶段四细化为独立协议）

以下为方向性约定，阶段四将制定完整协议：

| 项目 | 约定 |
|---|---|
| 干预 | `Mens E-Mail` |
| 对照 | `No E-Mail` |
| 结果 | `conversion` |
| 实验前特征 | `recency, history_segment, history, mens, womens, zip_code, newbie, channel` |
| **禁止作为特征** | `visit`、`spend`、`conversion` 及任何干预后字段 |
| 模型 | 简单 T-Learner（分别学干预组与对照组的结果预测，取差） |
| 基础学习器 | 第一轮固定一种（逻辑回归或树模型），不做模型竞赛 |
| 数据划分 | 训练 / 验证 / 最终留出集互不重叠，保持组别覆盖 |
| 预处理 | 只在训练集拟合 |
| 策略基线 | 随机选择 / 按购买概率选择 / 按预测增量选择，**在相同触达比例下比较** |
| 评估 | 固定留出集；不用购买预测 AUC 证明增量有效 |
| 条件化分配概率 | 记录从三组形成二组比较的规则与概率 |
