# 第三版 Agent 协议

目录维护更新：2026-10-12。节点顺序按当前graph.py核对，运行证据仍为最终验收冻结记录。

保留LangGraph和既有数据科学内核，指标协议、训练划分及策略参数沿用登记配置。

## 请求与状态

规则解析覆盖指标、比较双方、固定结果窗口、人群、排序、名单人数／比例。每项保存原文、值及resolved／clarification／unsupported状态，未解决条件阻止执行。未知表达需澄清，不承诺理解任意自然语言。

支持男装与无邮件、女装与无邮件，固定14天窗口，分母为全部随机分配客户。男装与女装直接比较、渠道及其他实验前筛选暂不支持；干预后分母筛选被阻断。客单价分母不明确时先澄清。多指标分别执行，主要与探索性角色独立显示。

## 流程与澄清

正常路径为 START → classify → plan → validate → execute → check → analyze → report → finalize → END。工具执行返回结果后做质量检查，通过才进入统计分析。validate可进入有限repair再回plan；execute仅对可重试故障有限重试；不支持、不可恢复故障或质量阻断进入收尾。

clarify结束当前轮次。补充回答读取同一线程，保留原问题及回答，带记录重新执行；支持部分回答后继续补充，不是LangGraph原生interrupt执行栈恢复。工作台根据当前终态立即显示控件，新会话清旧报告与控件，恢复核对线程归属。

validate与analyze共用model_resolution.resolve_model。合格模型必须匹配实验、数据版本、比较及所需完整分数。顺序：用户明确指定→配置默认→唯一合格候选；多个候选不按最新或名称自动批准。候选按训练时间展示，选择来源入计划。

## 报告与归档

最终分析报告通过结构化结果和程序模板生成，自由LLM解释不进入报告；旧解释守卫仅兼容历史。生成方式入explanation_guard.mode，模型不可用仍能完整分析。角色、方向、区间、p值、单位和局限由程序呈现。

所有登记入口共用_finish_run，保存原问题、补充回答、计划、报告、终态和工具证据，回填report_ref。完整导出包含版本、SHA256、实际SQL与参数；缺材料返回不完整。

replay仅做**效果重算**，不重放整个交互、名单或训练。先创建真实子运行，parent_run_id连接父记录；按历史参数执行并保存SQL和逐字段差异。缺证据或版本不匹配时报告未执行。

## 模型与评测

真实模型禁用SDK自动重试，DSA_MODEL_REQUEST_LIMIT可设进程请求上限。验收脚本另有持久账本；本线程用户明确取消原40次上限，保持批准的六题及公开数据范围；未知用量显式标记，费用未经核验不报告为0。

LLM基线获得完整工具schema和相同能力范围，允许answer／clarify／refuse；规则基线仅作消融。三者使用相同数据、题目、故障注入和契约。task_ok在所有检查后组合，completed只为其别名。完整终态与题目契约支持离线重新判分。旧记录见history/v2。

所有评测系统保存params、effective_params、完整result和result_sha256；故障注入后记录，规则消融动态取注册表。统计事实按局部子句及表格角色绑定，不以整行RR词影响差值区间。
